# macOS High Sierra (10.13.6) on the OptiPlex 780 + RX 640 — with full GPU acceleration

**Result (verified on the machine):** High Sierra 10.13.6 (17G66) boots with OpenCore 1.0.7 via OpenDuet on the legacy-BIOS
OptiPlex 780 (Core 2 Duo, no SSE4.2) and the Dell OEM RX 640 (Polaris 23, `0x6987`) is **fully accelerated**
(Metal, 4 GB, 1080p60 on the DisplayPort). It needed three things that don't exist in the other EFIs:

1. a **High-Sierra-specific injector** built from *High Sierra's own* AMD kexts (4 personalities),
2. **AAAMouSSE patched for xnu-4570** — the stock kext hooks the wrong kernel table slot on High Sierra (the key find),
3. the connector-reorder SSDT (same as Monterey) — and a monitor colour-format setting.

## Hardware / BIOS

| | |
|---|---|
| Machine | Dell OptiPlex 780, **legacy BIOS only**, Core 2 Duo (SSE4.1, **no SSE4.2 / POPCNT / AVX**) |
| GPU | Dell OEM RX 640, `1002:6987` rev `C1`, on the full-size DisplayPort of a Dell SE2717H |
| BIOS | **SATA Operation → "RAID Autodetect / AHCI"** (not "RAID On", not "Legacy"/ATA). Legacy USB on, TPM/TXT off |

## The recipe

Two OpenCore configs, generated by [`scripts/build_config_highsierra.py`](scripts/build_config_highsierra.py)
into [`EFI-HighSierra/EFI/OC/`](EFI-HighSierra/EFI/OC):

| | `config.plist` (stage 1) | `config-accel.plist` (stage 2) |
|---|---|---|
| Display | unaccelerated VESA (`-radvesa`) | **accelerated** |
| ACPI | Dell DSDT | + `SSDT-RX640-CONNECTORS.aml` (DisplayPort → framebuffer 0) |
| MouSSE | off | **patched `AAAMouSSE.kext`, first in the list** |
| boot-args | `-v keepsyms=1 debug=0x100 alcid=11 agdpmod=pikera -radvesa` | same without `-radvesa` |
| SIP | `csr-active-config 0x67` | `0x67` |
| SMBIOS | iMacPro1,1 | iMacPro1,1 |

Serial / MLB / UUID / ROM are placeholders in the repo — put your own into **both** configs
(`macserial -m iMacPro1,1 -g -n 1`) and run `ocvalidate` (OpenCore 1.0.7).

### Steps

1. **Installer USB.** Get the 10.13.6 installer volume (`createinstallmedia` result or a `.dmg` of it) and run
   `DISK=diskN USB_NAME="<media name>" USB_BYTES=<bytes> ./scripts/make_usb_highsierra.sh <volume-or-dmg>`
   (erases the stick; also fills random SMBIOS stand-ins on the stick copy only; the `.dmg` path clones block-level, so it
   works on hosts that cannot mount HFS+). If the old installer's certificate has expired, use the re-signed 10.13.6
   installer or `createinstallmedia` with the system date set back.
2. **Install (stage 1 config).** Boot the stick, pick *Install macOS High Sierra*, erase the target in Disk Utility as
   **Mac OS Extended (Journaled), GUID**, install, then boot the new volume through the USB's OpenCore.
3. **Build the bundle** on your Mac, copy it to the OptiPlex: `scripts/make_highsierra_bundle.sh ~/HighSierra-GPU-Setup`
   (injector builder, apply script, patched MouSSE, connector SSDT, internal-install script).
4. **Inject.** On the OptiPlex: `./install_injector.sh` — builds `RX640Injector.kext` from the installed system's
   `/System/Library/Extensions/{AMD9500Controller,AMDRadeonX4000,AMDRadeonX4000HWServices}` (4 personalities with
   `0x67FF1002` → `0x69871002`), installs it to `/Library/Extensions`, runs `kextcache -i /`. Needs `csr-active-config 0x67`
   (see "Gotchas").
5. **Switch config.** Mount the USB's `OPENCORE` partition and run `./apply_stage2.sh /Volumes/OPENCORE` (keeps your SMBIOS,
   saves the old config as `config-stage1.plist`, adds the SSDT + patched MouSSE). Reboot.
6. **Check.**
   ```bash
   system_profiler SPDisplaysDataType | grep -E 'Device ID|Metal|VRAM'     # 0x6987, Metal: Supported, 4 GB
   ```
   Purple/pink tint → Dell monitor menu → *Color → Input Color Format* → switch it to the other option — on this machine **YPbPr** fixed it (RGB fixed it on Monterey; it depends on what the monitor auto-detected).
7. **Boot without the USB.** `./install_to_internal.sh` (asks for `YES`, backs up sector 0 and the EFI partition to
   `~/ESP-backup-<date>`, copies the EFI + `boot`, writes OpenDuet's `boot1f32`/`boot0`). **Never mark the protective MBR active.**

## Why — the root causes we found

### 1. High Sierra *does* have Polaris support to retarget
`make_injector.py` finds four `0x67FF1002` personalities on 10.13.6 (`AMD9500Controller` ×2, `AMDRadeonX4000`
`AMDBaffinGraphicsAccelerator`, `AMDRadeonX4000HWServices` `…HWServicesPolaris`). With the real `0x6987` ID the chip
initialises (no `CAIL_ASICSetup() failed`) and Metal comes up. No spoof needed. (We first wrongly assumed Mojave/High Sierra
couldn't do it — the Monterey notes' "Mojave has no POLARIS23" was a static check, not a boot.)

### 2. `kextcache` refuses the unsigned injector with SIP on
```
Untrusted kexts are not allowed
Kext with invalid signature (-67062) denied: /Library/StagedExtensions/...  Unable to stage kext ... to secure location.
```
Boot with `csr-active-config 0x67` (both configs do) → `Kext with invalid signature (-67062) allowed`.

### 3. WindowServer crash-loop: `pcmpgtq` in the AMD OpenGL driver — MouSSE hooked the wrong slot
With the injector active, WindowServer died four times in a row (screen black, machine alive):
```
EXC_BAD_INSTRUCTION (SIGILL)    Logical CPU: 1
0 com.apple.AMDRadeonX4000GLDriver  glrATI_SI_InitMiscTextureInfo + 180     rip = base + 0x1cb3c
```
Disassembling the exact driver build (UUID `03AC29A1-DE03-3031-854D-B7F6D2018B4D`, extracted from the installer's `Core.pkg`)
shows `pcmpgtq %xmm6,%xmm0` — **SSE4.2**, absent on Penryn. Across all AMD binaries the Polaris path uses, there are only 18
such instructions (8 in `AMDRadeonX4000GLDriver`, 7 in `AMDSharedIL`, 3 in `AMDMTLBronzeDriver`), 0 in the kernel kexts.

AAAMouSSE 0.95 (the OCLP kext that emulates SSE4.2 on Monterey) loaded fine on High Sierra, logged
*"CPU does not natively support SSE4.2 … attempting #UD hook"* and still did nothing: a 40-run test program died every time,
on 1 CPU as well as 2. MouSSE swaps an entry of the kernel's `idt64_hndl_table0` for its own trap handler; it hardcodes
**byte offset 0x40**. In High Sierra's kernel (`xnu-4570.71.2`) that table is

| offset | entry |
|---|---|
| `0x28` | `hndl_alltraps` ← **the one that gets #UD** |
| `0x40` | `hndl_unix_scall` ← what MouSSE actually hooked (so it harmlessly passed syscalls through) |

([`scripts/patch_mousse_highsierra.py`](scripts/patch_mousse_highsierra.py)) changes the displacement byte `0x40 → 0x28` in the
3 instructions that touch the table (`0x254b`, `0x25d5`, `0x25e4`). The handler's other assumptions (`%r15` = saved state,
`trapno` at `+0xa0`, `%esi` = cs, exit via `_return_from_trap`) match 10.13.6. After the patch the test program
([`scripts/highsierra/ssetest.c`](scripts/highsierra/ssetest.c)) prints `ok=40 crashed=0` and the GPU stack comes up.
The patched kext is [`EFI-HighSierra/EFI/OC/Kexts/AAAMouSSE.kext`](EFI-HighSierra/EFI/OC/Kexts/AAAMouSSE.kext); the original is
kept in [`extras/AAAMouSSE-orig/`](extras/AAAMouSSE-orig).

### 4. "Stuck on the text console" after a failed injector run
`kextcache -i /` bakes `/Library/Extensions` personalities into `prelinkedkernel`. After the crashing stage-2 boot the next
boots (even safe mode `-x`, even `-radvesa`) reached `loginwindow` but never switched the display from the text console,
because the injector's personalities were still active. Fix: boot the USB installer → Utilities → Terminal →
[`scripts/highsierra/remove_injector_from_installer.sh`](scripts/highsierra/remove_injector_from_installer.sh) (removes the
injector and rebuilds the caches), then boot normally.

### 5. Purple tint
The desktop rendered but purple: the Dell SE2717H interpreted the DisplayPort colour format wrongly. Monitor menu →
*Color → Input Color Format* → switching it to **YPbPr** fixed it here (the Monterey notes fixed the same symptom with RGB — try the
other option). It is a monitor setting, not a GPU problem.

## Hardware H.264 decode (the Monterey `-radcodec` recipe works on High Sierra too)

Out of the box the accelerated GPU does **not** decode video: `VTIsHardwareDecodeSupported(H.264)` says YES (it is only a capability
claim), but a session that *requires* a hardware decoder fails with `-12913` (`kVTCouldNotFindVideoDecoderErr`) and VideoToolbox decodes in
software (`UsingHardwareAcceleratedVideoDecoder: no`). The video engine (`AMDRadeonX4000_AMDAccelVideoContext::getHWInfo`, present in
10.13.6) doesn't know PID `0x6987`. Fix = same as Monterey:

- `SSDT-RX640-CODEC.aml` (replaces `SSDT-RX640-CONNECTORS.aml`): same connector reorder + a `device-id` *property* `0x67FF` + `no-gfx-spoof`
  (WhateverGreen then doesn't spoof PCI config space, so CAIL still reads the real `0x6987`)
- boot-arg `-radcodec` (WhateverGreen replaces the PID seen by the video engine)

Apply on the machine: `scripts/highsierra/apply_codec.sh /Volumes/<EFI>` (backs up `config-before-codec.plist`; reboot).
Result on the OptiPlex (1080p30 High-profile H.264, 300 frames): `./hwdecode clip.mp4` **creates a hardware decoder, 198–330 fps**
(was: fails); `system_profiler` then shows `Device ID: 0x67ff`, Metal still `Supported`. HEVC hardware decode stays `no` on 10.13 (irrelevant).

Tools: [`scripts/highsierra/hwdecode.m`](scripts/highsierra/hwdecode.m) (modes: default = require hardware, `enable` = ask for hardware like
browsers do, `auto` = no preference — VideoToolbox's default on 10.13 is **software**, so apps must request hardware; Safari/AVFoundation
and Chromium do) and `vtcheck.c`. Build recipe and the CoreMedia/Swift-overlay gotcha are in `scripts/make_highsierra_bundle.sh`.

**Browsers:** YouTube serves VP9/AV1 to Chromium/Firefox-based browsers; on a Core 2 Duo that is decoded in software and stutters regardless
of the GPU. The GPU only helps if the page plays H.264 (Safari does; elsewhere use an H.264-forcing extension).

## Booting without the USB (internal disk)

`scripts/highsierra/install_to_internal.sh` copies `EFI/` + `boot` to the internal EFI partition and writes OpenDuet's `boot1f32` (PBR)
and `boot0` (MBR boot code, partition table untouched; never mark the protective MBR active). Without the stick:
`SRC_EFI=<folder with EFI/OC/config.plist> ./install_to_internal.sh` (e.g. an EFI built on another Mac and `scp`'d over). It backs up
sector 0 and the old EFI contents to `~/ESP-backup-<date>` and verifies every write. After it: shut down, unplug the stick, boot.
OpenCore does not need the stick once macOS is running — a machine booted from the stick keeps running after you unplug it, but would
not reboot, so check `ls /Volumes/EFI/EFI/OC` after `sudo diskutil mount disk0s1` before trusting it.

## Debugging notes (what did and didn't work for getting logs)

- OpenCore file logging (`Misc > Debug > Target = 67`) wrote **empty** `opencore-*.txt` files on OpenDuet's FAT32 — don't rely on it.
- High Sierra's `/var/log/system.log` has **no kernel messages**; the unified log has them:
  `sudo /usr/bin/log show --last boot | grep -i -E "AMD|mousse|rad:"`.
- Crash reports of the *installed* system are readable from the installer's Terminal at
  `/Volumes/<hd>/Library/Logs/DiagnosticReports/` (WindowServer reports gave the whole diagnosis).
- To get the exact faulting binary: `xar -xf Core.pkg Payload` from the installer's `InstallESD.dmg`, stream the pbzx payload,
  compare the crash report's image UUID with `otool -l … | grep -A1 LC_UUID`, then `otool -tvV` at `rip - image base`.

## Gotchas

- **SATA:** "RAID Autodetect / AHCI" in the BIOS, otherwise no disk in macOS.
- **SIP bits:** `0x67` is needed for the injector; with `0x00` the `kextcache` step silently drops it.
- **`kextcache -i /` is slow** on a Core 2 Duo (minutes) — don't interrupt it.
- **SMBIOS:** `iMacPro1,1` (the model Metal worked with here). `iMac10,1` would give native Penryn power management but is untested with this GPU.
- **Audio:** AppleALC `alcid=11` is configured but untested here; the VoodooHDA entry (disabled) works on High Sierra when injected by OpenCore.
- **Not covered:** sleep/wake, mini-DisplayPort outputs, hardware video *encode* (H.264 decode verified, see above).
